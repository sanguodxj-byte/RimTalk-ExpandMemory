[h2]📖 模组简介[/h2]
RimTalk-Expand Memory 是 RimTalk 的记忆拓展模组，为 AI 提供长期记忆系统、世界知识库以及自动遗忘与总结机制，让 AI 真正拥有"回忆"能力。

[i]完整功能介绍请参阅 [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3608181242]正式版创意工坊页面[/url]。[/i]


[h2]🚀 Beta 先行内容[/h2]
[h3]总结系统改进[/h3]
记忆总结系统已全面重构优化。
[list]
[*]AI 总结或归档请求失败时[b]不会破坏源记忆[/b]，相关记忆仍可参与下一次总结/归档，避免单次网络或模型故障导致的记忆丢失
[*]自动总结会按记忆的时间跨度智能分组：跨越多个游戏日时按天分别生成独立总结，避免长跨度记忆被压缩成一条"大杂烩"
[*]记忆时间线新增总结状态标记——已总结以紫色边框标注，正在总结以波动紫色边框标注
[*]构建总结提示词时会注入角色的[b]性别与年龄[/b]，生成的总结更贴合角色设定
[/list]

[h3]战斗记忆[/h3]
新增专门的战斗记忆捕获管线，让 AI 也能记得"打过什么仗"。
[list]
[*]补充捕获征召"坚守/开火"模式下由系统自动触发的攻击——此前这类攻击不创建工作（Job），无法被记录
[*]按攻击方式与战斗会话自动聚合：连发同一目标不重复计数，多目标时按命中数量汇总（如"连续射击了3个敌人"）
[*]可在设置中开关战斗记忆（默认开启）
[/list]

[h3]超短期记忆自动迁移[/h3]
超短期记忆（ABM）现在有了"保质期"。
[list]
[*]到期的超短期记忆会按设定时长自动迁入下层或移除，不再无限堆积
[*]迁移后可以被动态回忆
[*]可在设置中配置寿命（默认 24 小时，设为 0 关闭）
[/list]

[h3]多备选 API 与自动 fallback[/h3]
学习了 RimTalk 的 API 配置机制，AI 总结/归档调用支持配置多个 API 端点。
[list]
[*]改动 API 配置后即时生效，无需再重启游戏
[*]单次请求失败会自动切换到下一个配置
[*]"跟随 RimTalk 配置"开关在本版本中已修复可用，开启时自动复用 RimTalk 的云端配置
[i]鉴于总结/归档并不需要高性能模型，[b]依然建议为本模组单独配置一组 API[/b][/i]
[*]请求出错时会在日志中输出完备的错误信息
[*]新增 AI 日志开关，开启后会打印额外的请求细节
[/list]


[h2]🔧 重构与优化[/h2]
[h3]更准确的行动记忆捕获[/h3]
[list]
[*]普通工作仍只记录成功完成的行为，不再为被打断或失败的工作产生"幽灵记忆"
[*]战斗与施法等关键行为例外：即使中途被打断（目标死亡、移动、更换武器等）也会被记录，避免重要战斗与传送类能力施放漏记
[/list]

[h3]低频错峰 tick，性能更平滑[/h3]
[list]
[*]每个小人的记忆维护任务现在按哈希分散到不同 tick 执行，不再全员同步
[*]大幅平抑集中 tick 时的 CPU 峰值
[/list]

[h3]更合理的时间与衰减默认值[/h3]
[list]
[*]时间描述更口语化："一天前"改为"昨天"，归档层记忆直接显示年月日期
[*]重新调整了四层记忆的衰减速率与清理阈值，记忆生命周期更自然
[*]归档间隔默认从 7 天放宽到 15 天
[/list]

[i]此外，对项目内部结构进行了彻底重构、全面整理与废弃代码清理，为后续功能迭代打下更稳固的基础。[/i]


[h2]🐛 修复内容[/h2]
[list]
[*]修复手动固定某条轮次记忆时，其对应的原对象也被误固定的问题
[*]修复"跟随 RimTalk 配置"开启时模型抓取不正确的问题
[*]修复其他模组阻断响应生成时，未实际生成的回复仍被写入记忆的问题
[*]旧存档中中期/长期记忆的类型标记会自动校正为总结类型
[/list]

[h2]🤖 关于 AI 辅助开发[/h2]
本项目的开发过程中使用了 AI 辅助，但[b]并非[/b] vibe coding。[b]我们充分了解项目架构和运作原理，也很清楚改动目标和实现方案，且会逐行阅读、彻底了解每一处改动。[/b]

大致工作流如下：
[list]
[*][b]方案讨论[/b]：先与 AI 充分讨论设计与实现方案
[*][b]初步执行[/b]：由 AI 生成初版代码
[*][b]人工接管[/b]：基于实际需求改动框架、细化模块、优化代码——AI 还是差点意思，最后大多数时候都是完整的重写一遍
[*][b]AI Review[/b]：最终由 AI 对人工重写的代码进行审查（这一步 AI 确实权威）
[/list]
