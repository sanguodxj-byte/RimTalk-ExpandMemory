# MainTabWindow_Memory UI 重写概念设计

## 1. 文档目的

本文档定义 `MainTabWindow_Memory` 完全重写后的产品定位、信息架构、核心交互与视觉方向，作为后续原型和实现工作的设计基线。

本文档关注用户看到什么、如何理解信息以及如何操作，不讨论代码结构、技术选型或具体实现方案。

### 1.1 重写与职责边界

本轮工作是从零开始的新 UI，不要求也不倾向保留旧 `MainTabWindow_Memory` 的结构、目录、类名、文件拆分或绘制方式。旧 UI 仅用于核对已有业务功能，不能作为新界面的结构参考。新界面将以新的 UI 类注册替换旧入口，使旧实现直接失效。

新 UI 与业务逻辑保持解耦：

- UI 负责读取展示数据、维护界面状态、绘制内容并下发用户命令。
- UI 可以直接读写业务对象公开字段，也可以承担与呈现紧密相关的轻度逻辑。
- 总结、归档、维护、导入导出等具有独立业务语义或较高复杂度的操作，应由接收命令的业务对象完成。
- 不在 UI 中复制或重新实现已有业务规则。

当前 UI 采用一个主标签会话上下文供五个区域共享：主窗口只负责生命周期、布局和绘制派发；顶部栏、篇章区、时间流、详情栏和选择栏各自由独立实例绘制。会话上下文组合全局单一 UI 状态与当前记忆组件的派生展示模型，只在固定后引用替换、失效选择清理和批处理等需要同步多个状态时提供协调方法。

## 2. 产品定位

新界面定位为 **角色人生档案工作台**。

它同时承担两个互补角色：

- **角色人生时间线**：帮助玩家理解某个 Pawn 经历过什么、记住了什么，以及这些经历如何逐渐形成阶段总结和长期篇章。
- **记忆管理工作台**：帮助玩家查看详情、编辑记忆、固定重要内容，并对明确选中的记忆执行总结、归档和删除。

界面首先服务普通玩家。ABM、SCM、ELS、CLPA 等内部缩写不应成为理解界面的前提，默认使用自然语言表达：

| 内部层级 | 面向玩家的名称 | 主要含义 |
|---|---|---|
| ABM | 近期经历 | 刚刚发生的对话、行动和事件 |
| SCM | 短期记忆 | 暂时保留、仍较活跃的具体经历 |
| ELS | 阶段总结 | 对一段具体经历的总结 |
| CLPA | 人生篇章 | 覆盖较长时间跨度的长期归档 |

内部缩写可以出现在 Tooltip 或详情栏的技术信息区域，但不作为主界面的主要文案。

## 3. 设计原则

### 3.1 先读懂人生，再管理数据

时间、人物、正文和阶段关系是第一层信息。层级、活跃度、总结状态和批量操作是辅助理解与管理的第二层信息。

### 3.2 时间流表达事件顺序，篇章栏表达真实跨度

记忆生成密度并不均匀。短时间内可能产生大量条目，也可能很长时间没有任何记忆。因此：

- 纵向时间流采用内容驱动布局，表达先后关系，但不以像素距离严格代表真实时间。
- 横向人生篇章导航器采用真实时间尺度，表达 CLPA 的起止范围和人生全局位置。
- 时间流中的长时间空白不显示明确的间隔文案，仅可增加少量留白，帮助玩家感知时间跳跃。

### 3.3 普通操作显性，危险操作必须明确

- 手动创建记忆使用明确的“新建记忆”入口，不再依赖隐藏的右键操作。
- 批量操作只作用于明确选中的记忆。
- 不再保留“未选中时等于操作全部可见记忆”的隐式规则。
- 全量操作必须作为独立动作呈现，并提供清晰确认。

### 3.4 低频工具不干扰主任务

注入预览、总结提示词、常识库、导入导出和操作指南统一收纳到“工具”菜单中。

### 3.5 与 RimWorld 融合，但保持独特识别

界面采用“原生档案 + 角色编年史”的混合风格：

- 窗口框架、字体、按钮、菜单、Tooltip 和基础反馈保持 RimWorld 原生语言。
- 时间流通过时间脊线、年/象章节、阶段总结节点体现编年史感。
- 详情栏采用克制、规整的档案式字段结构。
- 篇章导航器使用简洁的时间刻度、跨度条和光标。
- 不要求引入外部纹理素材，避免与原版 UI 割裂。

1. 顶部操作栏
2. 横向人生篇章导航器
3. 纵向记忆时间流
4. 右侧常驻详情栏
5. 底部选择操作栏

## 5. 顶部操作栏

### 5.1 Pawn 选择与自动跟随

- 使用支持搜索的 Pawn 下拉选择器。
- 可以选择殖民者、囚犯、奴隶及其他有效类人生物，并以自然分组或身份标识帮助辨认。
- 当玩家在世界中选中有效 Pawn 时，主窗口自动切换到该 Pawn。
- 点击地图 Pawn 或殖民者头像时，记忆主窗口保持打开，不执行原版的自动关闭主标签行为。
- 在顶部选择 Pawn 时，同时同步 RimWorld 当前选择对象，形成双向一致。
- 玩家选中建筑、物品、空地或取消选择时，主窗口继续保持当前 Pawn，不清空上下文。
- 关闭后重新打开窗口时，若当前未选中 Pawn，则优先恢复上次查看的 Pawn，而不是重新选择默认 Pawn。

### 5.2 标签筛选

本轮将标签筛选视为占位能力，以简单、稳定为优先。后续可扩展为多标签筛选或更完整的查询能力。

筛选功能扩展后应遵循：

- 仅显示匹配结果。
- 年、象和 ELS 节点显示匹配数量。
- 自动展开通往匹配结果的层级路径。
- 组复选框只选择当前筛选结果，不包含被筛选隐藏的记忆。

### 5.3 新建记忆

顶部提供明确的“新建记忆”按钮。创建流程使用自然语言选择目标层级：近期经历、短期记忆、阶段总结或人生篇章。

### 5.4 工具菜单

工具菜单集中收纳：

- 常识库管理
- 注入预览
- 总结提示词编辑
- 记忆导入与导出
- 操作指南
- 其他低频或调试工具

## 6. 人生篇章导航器

人生篇章导航器位于时间流上方，只横跨时间流区域，不侵入右侧详情栏。它由两个上下排列的部分组成：

- **篇章主要区域**：绘制 CLPA 人生篇章跨度。
- **时间轴区域**：绘制时间刻度和当前阅读时间光标。

时间方向统一为左旧右新。

### 6.1 导航器概念图

```text
篇章主要区域
┌────────────────────────────────────────────────────────────────────┐
│     ┌──────── 开拓初期 ────────┐                                  │
│                ┌──── 袭击与重建 ───────────┐                       │
│                         ┌──── 新殖民地生活 ───────────────┐         │
│                                  [ +3 重叠篇章 ]                    │
├────────────────────────────────────────────────────────────────────┤
│ 5502年              5503年              5504年              5505年 │
│                                           ▲                        │
│                                      阅读时间光标                  │
└────────────────────────────────────────────────────────────────────┘
时间轴区域
```

### 6.2 默认时间范围与缩放

- 每次切换 Pawn 时，不保留前一个 Pawn 的篇章缩放状态。
- 默认时间窗口为 RimWorld 原版一年，即 60 个游戏日。
- 时间轴区域上的滚轮用于动态缩放。
- 篇章主要区域与时间轴使用同一时间窗口并同步缩放。
- 缩放时优先保证可见范围不超出该 Pawn 的完整时间轴边界。
- 未触及完整时间轴边界时，缩放前后保持光标在窗口中的绝对横向位置不变。例如缩放前位于 1/3 处，缩放后仍位于 1/3 处。

### 6.3 阅读时间光标

阅读时间光标是篇章导航器与时间流之间的统一锚点。

- 光标对应时间流可视区域中央附近的节点或卡片。
- 光标可以位于篇章时间轴上的任意横向位置，不固定在中央。
- 在篇章主要区域滚轮时，只平移篇章主要区域和时间轴视窗，不改变阅读光标代表的时间，也不移动时间流。
- 在时间轴上点击或拖动时，可快速移动光标。
- 主动移动光标时，把时间流中时间最接近的可见节点定位到视窗中央，但不额外平移篇章视窗。
- 主动滚动时间流时，只更新光标在当前篇章视窗中的位置；篇章视窗本身保持不动。
- 当时间流把光标推到当前篇章视窗之外时，才平移整个篇章视窗，并让光标贴在相应的左端或右端。
- 当光标落在篇章有内容、但时间流没有节点的时段时，选择绝对时间最近的可见节点；距离相同时偏向较新的节点。

### 6.4 双向同步规则

```text
主动移动光标

连续移动光标
      ↓
寻找时间最接近的可见节点
      ↓
时间流跳跃定位并将该节点置于视窗中央


滚动篇章主要区域

整体平移篇章内容、时间轴和光标
      ↓
时间流保持原位


时间流主动滚动

滚动时间流
      ↓
读取视窗中央附近节点的时间
      ↓
光标跳跃到该节点对应时间
      ↓
若光标仍在篇章视窗内：篇章视窗保持不动
若光标越界：平移篇章视窗并将光标保持在边缘
```

两种方向有意采用不同反馈：

- 光标到时间流：光标连续，时间流按离散节点跳跃。
- 时间流到光标：时间流连续滚动，光标按中央节点离散跳跃；仅在越界时带动篇章视窗。
- 篇章视窗平移：时间流和光标代表的阅读时间均不改变，只改变可见时间范围。

### 6.5 点击语义

- 点击 CLPA 跨度条或卡片：选中该 CLPA，并在详情栏显示内容。
- 点击或拖动其旁边的时间轴：移动光标，并定位时间流。
- 跳转到已折叠时段时：定位对应的年、象或 ELS 折叠节点，不自动改变用户的折叠状态。

### 6.6 CLPA 重叠

CLPA 允许按真实时间范围重叠绘制，新 CLPA 获得视觉和点击优先级。

为保证极端重叠或完全重叠时每条 CLPA 仍可访问：

- 较新的 CLPA 后绘制并位于上层。
- 被覆盖的篇章保留少量错位边缘，形成档案叠放感。
- 重叠区域显示篇章数量入口，例如 `+3`。
- 点击数量入口后，显示该重叠区域内的全部 CLPA，并按新到旧排列。
- 用户可以从列表中选择任意 CLPA 打开详情。
- 悬浮重叠区域时，提示覆盖该时间点的篇章数量及摘要信息。

## 7. 纵向记忆时间流

时间流按最新在上、向下回溯过去的方向排列。

### 7.1 语义时间脊线

时间流使用明确但克制的纵向时间脊线，表达顺序、分组和折叠关系。脊线不是严格的时间坐标轴：

- 条目高度由内容类型和摘要长度决定。
- 密集发生的记忆可以连续排列。
- 较长无记忆时段只增加少量视觉留白。
- 真实时间跨度由上方篇章导航器承担。

### 7.2 时间层级

时间流形成以下层级：

```text
年
└─ 象
   ├─ ELS 阶段总结
   │  ├─ ABM 近期经历
   │  └─ SCM 短期记忆
   └─ 未被 ELS 覆盖的具体经历
```

- 年、象是高层时间章节，默认展开，但允许手动折叠。
- ELS 是细粒度折叠节点。
- 最近 3 个游戏日的具体经历默认展开。
- 较早的具体经历默认折入相邻 ELS 节点。
- 没有 ELS 覆盖的经历继续显示在对应年、象章节下。

### 7.3 ELS 时间范围推断

当前 ELS 没有保存完整来源范围，因此时间流只依据时间边界进行展示推断：

- 一条 ELS 收纳“前一条 ELS 之后，到当前 ELS 时间为止”的 ABM 和 SCM。
- 手动跨时段总结、重复总结等情况可能使展示分组与真实总结来源不完全一致。
- UI 不应声称折入条目就是该 ELS 的精确来源，只将其表达为同一推断时段内的经历。
- 本次重写不为此扩展记忆数据模型。

### 7.4 不同记忆类型的信息密度

| 类型 | 时间流表现 |
|---|---|
| 行动记忆 | 接近单行日志，突出时间、行动摘要和相关对象 |
| 对话记忆 | 显示参与者及 2 至 4 行内容摘要 |
| ELS 阶段总结 | 较大的总结节点，显示总结摘要、推断时段、折入数量和展开状态 |
| CLPA 人生篇章 | 主要显示在篇章导航器中；选中后在详情栏查看完整内容 |
| 手动记忆 | 遵循所属类型的密度，附加低调的“手动记录”标识 |

### 7.5 Activity 与 Importance

Activity 必须在时间流中持续可见：

- 每条具体记忆使用精确的细 Activity 条。
- Activity 较低时，时间节点逐渐空心化或降低节点填充强度。
- 低活跃视觉反馈不能通过降低正文可读性实现。
- 极低活跃记忆可以显示“正在淡忘”一类状态提示。

Importance 不需要始终显示精确进度：

- 普通重要性不占用时间流空间。
- 高重要性可使用克制的星标或强调标识。
- 精确数值在详情栏中显示。
- 固定记忆使用清晰的图钉或书签标识。

四层记忆采用一致的低饱和颜色编码：

- 近期经历（ABM）：蓝青色。
- 短期记忆（SCM）：绿色。
- 阶段总结（ELS）：琥珀色。
- 人生篇章（CLPA）：紫色。

颜色主要用于节点、卡片边框和轻微背景染色，不降低正文对比度。每张记忆卡片提供明确的固定/取消固定快捷按钮，固定状态同时使用金色强调，不能只依赖难以辨认的小型文本符号。

### 7.6 选择与组选择

- 单条记忆支持普通单选、Ctrl 多选、Shift 范围选择和拖拽框选。
- 年、象和 ELS 节点提供组复选框。
- 选择 ELS 节点时，选择范围包含 ELS 自身及其下当前可选择的具体经历。
- 筛选启用时，组选择仅包含当前筛选结果。
- 折叠和选择是两种独立状态，点击章节标题不等同于选择整组。

## 8. 右侧详情栏

详情栏常驻于窗口右侧，与篇章导航器互不占位。详情栏宽度可拖拽调整。

### 8.1 查看状态

任何 `MemoryEntry` 都可以进入详情栏，包括 ABM、SCM、ELS 和 CLPA。

详情栏负责展示时间流中不适合常驻的完整信息：

- 完整正文
- 准确日期或可用的时间范围
- 自然语言层级与记忆类型
- 标签
- 相关人物
- 地点
- Importance 精确值
- Activity 精确值
- 备注
- 固定状态
- 总结状态

可提供默认折叠的技术信息区域，用于显示层级缩写、ID、OriginId 等内部字段，但不干扰普通玩家阅读。

### 8.2 编辑状态

详情栏默认只读，点击“编辑”后原位进入编辑状态。

- 进入编辑状态时立即暂停游戏，并在编辑状态持续期间保持暂停。
- 编辑已有记忆时允许正文为空；新建记忆仍要求填写正文。

允许编辑：

- 正文
- 备注
- 标签
- Importance

固定状态只通过时间流和篇章卡片上的固定按钮修改；详情编辑不改变所有权，也不会触发 `RoundMemory` 私有化。

层级保持只读，避免直接迁移记忆破坏其生成和折叠语义。类型是否允许修正可在后续原型中谨慎评估，默认不作为主要编辑能力。

### 8.3 空状态

未选择记忆时，详情栏暂时显示由字符串常量提供的使用说明。该区域预留给后续安排，不在本设计阶段继续扩展。

## 9. 底部选择操作栏

底部操作栏只在存在明确选择时出现或激活，并显示当前选中数量。

主要动作包括：

- 总结选中记忆
- 归档选中记忆
- 删除选中记忆
- 清除选择

操作按钮应根据当前选择中可处理的层级显示有效数量和可用状态。危险操作必须明确提示目标数量并要求确认。

## 10. Pawn 切换与阅读位置

### 10.1 窗口保持打开时切换 Pawn

- 阅读光标、篇章缩放、筛选和折叠状态属于主标签共享会话状态，切换 Pawn 时继续沿用。
- 切换时清空焦点和选择，避免对新 Pawn 操作旧引用。
- 在新 Pawn 时间流中定位绝对时间最接近的可见节点并置于中央。
- 若两个 Pawn 的记忆时间跨度差异过大，仍以最近可用节点为准。

### 10.2 关闭后重新打开窗口

- 主窗口实例仍有效时保留共享会话状态。
- 当前 `FourLayerMemoryComp` 已离开当前地图或失效时，清空组件、焦点和选择。

### 10.3 游戏暂停时的临时保留

- Pawn 未改变且窗口保持打开时，光标持续保持当前位置。
- 切换 Pawn 后再切回时继续使用同一份共享阅读光标，不维护 Pawn 私有位置副本。

## 11. UI 状态生命周期

UI 状态分为跨会话布局偏好和当前主标签共享会话状态。

### 11.1 跨存档保留的全局布局偏好

写入 Mod Config，适用于所有存档和 Pawn：

- 时间流宽度
- 其他与具体 Pawn 无关的页面布局偏好

### 11.2 仅当前运行会话保留的主标签共享状态

不写入游戏存档，退出游戏或重新载入后重置：

- 阅读时间光标
- 时间流滚动位置
- 年、象和 ELS 的折叠状态
- 当前选择状态
- 标签、层级和类型筛选
- 篇章导航器缩放与视窗中心

以上状态只有一份，切换 Pawn 时不创建或恢复 Pawn 私有状态对象；焦点和选择在切换组件时清空。

## 12. 视觉语言

### 12.1 原生部分

- 使用 RimWorld 原生字体等级和交互反馈。
- 按钮、菜单、确认窗口和 Tooltip 保持原生行为。
- 基础背景采用深色、低对比面板。
- 不使用大面积高饱和层级色。

### 12.2 编年史部分

- 纵向时间脊线连接年、象、ELS 与具体经历。
- 年和象使用章节标题或档案索引式标记。
- ELS 使用区别于普通经历的总结节点。
- CLPA 使用横向跨度条表达人生篇章。
- 时间节点形态同时承担 Activity 状态表达。

### 12.3 状态色原则

- 层级颜色作为边缘、节点或小型标记使用。
- 选中状态拥有最高视觉优先级。
- 总结中、已总结、固定、低活跃等状态互不覆盖，采用可叠加的小型标识。
- 正文可读性不随 Activity 降低。

## 13. 功能基线

重写后应保留或改善以下已有能力：

- 选择 Pawn，并可查看所有有效类人生物
- 查看四层记忆数量和状态
- 按层级与类型筛选
- 按时间浏览记忆
- 查看完整正文及相关信息
- 单选、多选、范围选择和框选
- 固定与取消固定
- 编辑记忆
- 查看总结中和已总结状态
- 批量总结、归档和删除
- 总结全部殖民者
- 手动创建四层记忆
- XML 导入与导出
- 打开常识库、注入预览、总结提示词和操作指南

现有功能可以重新组织入口和交互，但不应无故丢失。

## 14. 当前不扩展的范围

本轮概念设计明确不包含：

- 新 UI 内部的具体类拆分、方法设计或控件级实现
- 性能优化方案
- ELS 来源 ID 或时间范围数据模型扩展
- 常识库主窗口的整体重写
- 注入预览、总结提示词等独立工具窗口的完整重写
- 标签搜索的高级查询能力
- 外部纹理和美术资源制作
- 具体像素尺寸、颜色值和动画参数

创建与编辑记忆等直接耦合的交互窗口允许随主窗口统一调整，以保持体验一致。

## 15. 后续设计阶段的验证重点

后续原型应优先验证以下体验问题，而不是立即追求视觉完成度：

- 在 1200 像素左右宽度下，时间流与可调详情栏是否都保持可读。
- 篇章导航器的光标、缩放和时间流跳转是否容易理解。
- 时间流高密度与低密度记忆混排时，语义时间脊线是否稳定。
- ELS 推断折叠是否会让玩家误认为存在精确来源关系。
- CLPA 多重或完全重叠时，所有篇章是否仍可发现和选择。
- 年、象、ELS 三级结构是否造成过多点击层级。
- Activity 细条和空心节点是否能表达淡忘状态而不制造视觉噪声。
- 批量选择、组复选框与筛选共同使用时，操作目标是否始终明确。
