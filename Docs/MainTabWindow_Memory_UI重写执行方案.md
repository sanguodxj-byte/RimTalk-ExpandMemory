# MainTabWindow_Memory UI 重写执行方案

## 1. 目标与依据

本方案用于指导 `MainTabWindow_Memory` 及其直接关联创建、编辑交互的完整重写。

设计与验收以根目录 `MainTabWindow_Memory_UI重写概念设计.md` 为总纲。后续若设计发生变化，应先同步更新概念设计，再调整本执行方案。

## 2. 执行原则

- 以现有功能完整保留为底线，以新概念设计为交互基准。
- 从零建立新 UI，不保留旧主窗口的结构、目录、命名、文件拆分或写法。
- 新代码统一放在 `Source/UI/`，采用新的命名和拆分结构。
- 通过修改 Def 注册新的主窗口类，使旧 UI 快速失效；旧文件仅在确认替代完成后处理。
- 旧 UI 只用于盘点功能和外部业务入口，不作为新实现的参考或复用来源。
- UI 只负责绘制、界面状态和命令下发；复杂业务逻辑由接收命令的业务对象封装执行。
- UI 可直接读写公有字段并承担轻度呈现逻辑，但不得复制总结、归档、维护等业务规则。
- 先建立稳定的信息结构和状态规则，再完善视觉表现。
- 分阶段形成可运行、可验证的界面，避免一次性替换全部功能。
- 不扩展 ELS 来源数据模型，不重写常识库等独立工具窗口。
- 不修改与本轮 UI 重写无关的记忆捕获、维护、总结和注入逻辑。
- 每阶段完成后同步检查概念设计、功能基线和实际行为是否一致。

## 3. 执行阶段

### 阶段一：基线与边界整理

主要行动：

- 盘点主窗口现有功能、外部业务入口和命令接收方。
- 明确旧 UI 仅作为功能核对清单，不继承其结构、命名和交互写法。
- 确认应由 UI 下发的命令，以及应继续由业务对象承担的复杂逻辑。
- 明确跨会话布局偏好与主标签共享会话状态的边界。
- 准备覆盖高密度、低密度、跨年、CLPA 重叠等场景的测试数据。

阶段产物：

- 现有功能到新界面区域的对应清单。
- UI 命令与业务接收方的职责边界清单。
- 重写边界和验证场景清单。

通过条件：

- `UI层.md` 中记录的现有功能均有明确去向。
- 概念设计中的核心状态规则无遗漏或冲突。

### 阶段二：主窗口骨架

主要行动：

- 在 `Source/UI/` 从零建立新的 UI 命名与拆分结构。
- 建立顶部操作栏、篇章导航区、时间流、可调详情栏和底部选择栏的整体结构。
- 修改 Def，使主标签注册到新的主窗口类并停止使用旧 UI。
- 接入 Pawn 搜索选择与世界选择自动跟随。
- 建立全局布局偏好和主标签共享会话状态。
- 完成无 Pawn、无记忆组件、无记忆和未选中详情等空状态。

阶段产物：

- 可在游戏中打开、切换 Pawn 并稳定保持布局的主窗口骨架。

通过条件：

- 主窗口在目标分辨率下无区域重叠或不可访问内容。
- 游戏入口只实例化新的主窗口类，旧 UI 不再参与运行。
- Pawn 双向选择、非 Pawn 选择保持当前目标等规则正确。
- 详情栏宽度可调整并跨存档保留。

### 阶段三：纵向记忆时间流

主要行动：

- 将 ABM、SCM、ELS 按年、象和 ELS 推断时段组织为纵向时间结构。
- 完成年、象、ELS 的展开与折叠，以及最近 3 天默认展开规则。
- 按行动、对话和阶段总结提供不同的信息密度。
- 加入语义时间脊线、长时间空白留白和 Activity 视觉表达。
- 恢复单选、多选、范围选择、框选和组复选框。

阶段产物：

- 可独立浏览和选择记忆的完整时间流。

通过条件：

- 高密度和低密度记忆均可稳定阅读。
- ELS 折叠范围符合“前一 ELS 之后至当前 ELS”的推断规则。
- 折叠、筛选与组选择不会造成操作目标歧义。
- Activity 精确细条及低活跃节点状态清晰且不影响正文可读性。

### 阶段四：人生篇章导航器

主要行动：

- 建立左旧右新的横向时间轴和 CLPA 跨度区域。
- 加入默认 60 天窗口、以光标为中心的缩放和平移。
- 完成光标、篇章区和时间流的双向同步。
- 支持时间轴点击、拖动和滚轮操作。
- 处理无时间流节点时的最近节点定位，以及折叠时段定位。
- 完成 CLPA 重叠绘制、最新篇章优先和重叠篇章选择入口。

阶段产物：

- 可用于全局定位、缩放和选择 CLPA 的人生篇章导航器。

通过条件：

- 篇章导航器主动操作时，光标连续移动且时间流正确跳转。
- 时间流滚动时，光标按中央节点正确更新。
- 局部重叠、完全重叠和大量重叠情况下，每条 CLPA 均可被选择。
- 切换 Pawn、切回 Pawn和重新打开窗口时的定位规则符合总纲。

### 阶段五：详情与编辑

主要行动：

- 完成所有 `MemoryEntry` 类型的统一详情展示。
- 加入详情查看与原位编辑状态切换。
- 支持正文、备注、标签、Importance 和固定状态编辑。
- 保持层级只读，并区分玩家信息与折叠的技术信息。
- 统一调整直接关联的创建和编辑交互。

阶段产物：

- 可查看并安全修改普通记忆、阶段总结和人生篇章的详情栏。
- 与新主窗口风格一致的新建记忆流程。

通过条件：

- 保存、取消和切换选择不会造成意外修改。
- 编辑结果能立即反映到时间流、篇章栏和筛选结果。
- 四层记忆均可通过自然语言入口创建。

### 阶段六：操作闭环与工具入口

主要行动：

- 接入总结、归档、删除、固定等现有业务动作。
- 所有复杂动作均通过对应业务对象接收命令，UI 不承载重复业务实现。
- 建立只对明确选择生效的底部批量操作栏。
- 为全量和危险操作提供独立入口及确认反馈。
- 将常识库、注入预览、总结提示词、导入导出和操作指南集中到工具菜单。
- 保留总结中、已总结等现有状态反馈。

阶段产物：

- 从浏览、选择、编辑到批量治理的完整操作闭环。

通过条件：

- 不存在“未选择即操作全部”的隐式行为。
- 各操作只处理合法层级，并准确显示目标数量。
- 现有导入导出和独立工具入口均可正常使用。

### 阶段七：视觉统一与体验收尾

主要行动：

- 统一原生档案与角色编年史的混合视觉语言。
- 调整信息密度、层级色、选中状态、Tooltip 和空状态。
- 校正不同窗口尺寸、语言长度和大量记忆场景下的布局。
- 确认新 UI 完整替代后，再清理废弃的旧主窗口目录与代码。
- 补齐翻译文本和使用说明占位内容。

阶段产物：

- 视觉和交互一致的重写版本。

通过条件：

- 界面融入 RimWorld 原生风格，同时保持清晰的编年史识别。
- 不依赖外部纹理也能完整表达层级、跨度和状态。
- 常用操作无需依赖隐藏入口或技术缩写。

## 4. 最终验证

完成全部阶段后统一验证：

- 对照概念设计逐项检查核心交互与状态生命周期。
- 对照现有 UI 功能清单检查功能保留情况。
- 验证 RimWorld 1.5 与 1.6 构建和加载。
- 验证新旧存档、无记忆 Pawn、非殖民者 Pawn 和多地图场景。
- 验证大量记忆、长对话、跨年记录、CLPA 重叠和异步总结状态。
- 验证导入导出、创建、编辑、总结、归档和删除的数据正确性。
- 验证切换 Pawn、暂停/恢复游戏、关闭/重开窗口后的阅读位置与 UI 状态。
- 完成最终回归后，再移除确认无用的旧 UI 文件或代码。
- 检查新代码仅位于新的 `Source/UI/` 结构中，未延续旧 UI 的目录、类名和拆分方式。
- 检查 UI 未承载总结、归档、维护等复杂业务规则。

## 5. 文档维护

- `MainTabWindow_Memory_UI重写概念设计.md` 记录设计目标与交互规则，是最高层设计依据。
- 本文档记录执行顺序与阶段验收，随设计总纲同步调整。
- `UI层.md` 在重写完成后更新为新 UI 的实际结构和功能说明。
- 阶段推进中发现的设计冲突，应先回写概念设计，不在实现中形成未记录的隐式规则。
